# Long Multi-Shot FL2VA joint windows

The existing `longvid_multishot_hardcut` mode now compiles camera slots into joint native FL2VA-family AV windows. Authored slot boundaries are not sampler boundaries. A 15-second, four-slot board is one 362-frame technical sample, delivered as 360 frames. Images, IDs, start frames, duration and local prompts come from the current Shotboard rows. There is no A/B-specific backend code or fixed shot count.

The multishot compiler uses the full native 362-frame window instead of inheriting a smaller window saved for another LongVid engine. Each intersecting visual slot is also sent to the multimodal text encoder in the same dynamically numbered Picture order used by its prompt. AddGuide alone does not publish those pictures to the text encoder. Each enabled image contributes a stock MiniMaxH3AddGuide at its authored start inside the applicable window. Local prompt intervals and generated hard-cut instructions follow the same start/end frames. No synthetic final-image reanchor, repeated end image, decoded image replacement or still-frame hold is added. AddGuide remains a model keyframe constraint, so generated cut precision and freedom from visual interpolation require GPU validation; this implementation does not promise deterministic edit cuts from a jointly sampled latent.

Longer boards retain one latent per technical window. Successor windows use the existing sampled AV-tail mechanism with a hidden 22-frame prefix, trimmed once from delivery. Images whose slots cross a technical boundary are not reinserted. Their local prompts remain active for the intersecting interval. Window timing advances only by visible frames.

Custom audio uses an absolute AudioBoard clock. Unlinked long audio spans all angles; explicitly linked clips are intersected with the linked authored slot rather than a synthetic technical-window slot. Native H3 audio is generated jointly within each window and carried through the sampled AV tail at technical boundaries. Custom audio is locked before sampling and restored from its original waveform during delivery.

Scout bypasses this mode because independent candidates would discard latent history. Other public modes keep their existing compiler and routing behavior. CPU regression suites cover the existing Continuous AV/router and extension contracts as well as the new multishot clock. Syntax checks and the supplied dialogue WAVs were verified. No GPU render was performed for this revision.
